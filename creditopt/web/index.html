How much should the optimiser do?

Our quality commitment
  • Cheapest that will do it well, not just the cheapest. Model choice is based on what the task needs. On "Best quality", borderline calls go to the stronger model.
  • Savings come from waste, not corners. Search output goes to cheap helpers, routine edits to cheaper models, and stale context gets cleared. The model doing the thinking keeps its full ability.
  • Every run is told to do the task properly, not to economise on tokens.
  • Work is checked when you allow it: your tests are run, and an Opus reviewer reads the diff against your request.
  • Unfinished work gets a stronger model. It's resumed (up to your chosen limit) and keeps what's been done so far.
  • Honest results. Every run reports done, done but not tested, or incomplete, says what wasn't verified, and shows exactly what it cost.
  • You're in charge. Every one of these can be changed above, and the model can always be overridden.

Automate it inside Claude Code

One command wires three things into Claude Code. It's a dry run unless you add --apply, and settings.json is backed up first.

  1. Context guard hook: warns you before each prompt once context nears your budget, when you return to a cold cache, and when a trivial prompt is about to go to Opus.
  2. Status line: a live context meter that turns amber, then red, as compaction becomes due.
  3. Automatic compaction: Claude Code compacts by itself when a conversation reaches your compact budget, instead of waiting until it's nearly full. Changing the budget below updates it; removing the add-ons restores Claude Code's default.
  4. Cost-aware subagents: scout (Haiku, exploration), runner (Haiku, tests/builds) and architect (Opus, design advice for Sonnet sessions).

Or from a terminal, in the creditoptimiser folder:

python3 -m creditopt install --apply
